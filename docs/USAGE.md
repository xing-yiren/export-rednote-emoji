# 使用说明

## 环境

- macOS，Chrome（实测 155.0.8059.85）或 Edge（Chromium 内核，待实测版本 ≥ 120）
- 需要能正常登录小红书网页版

## 安装（开发者模式）

1. 构建：`npm install && npm run build`，产物在 `dist/`。
2. 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择项目下的 `dist/` 目录。

## 使用流程

1. 手机端把要导出的收藏表情，发到一条方便管理的帖子评论里（是否可见遵循平台规则）。
2. Mac 浏览器打开该帖子，**手动展开评论与回复**，让目标图片渲染出来。
3. 点击工具栏扩展图标：
   - 首次会请求读取小红书图片域名的权限，请允许；
   - 自动打开管理页，并在笔记页开始采集。
4. 管理页中：
   - 图片默认全选，可按作者、状态筛选；
   - 点击“获取所选”读取并校验图片字节（格式、尺寸、SHA-256）；
   - 单张点“保存”，或“导出 ZIP”批量导出；
   - 导出目录包含 `images/`、`manifest.json`、`failures.json`。
5. 需要继续采集时，回到小红书标签页滚动或展开评论；管理页会自动更新。
6. 结束时点击“停止采集”。

> 管理页打开后，小红书页面的详情弹层通常会关闭、评论区 DOM 被卸载。这是正常现象：已采集的数据保存在扩展本地，仍可继续获取与导出；但需要继续采集时必须回到小红书页重新展开评论。

## 已知限制

- 只采集**已渲染**的评论图片，不代表整帖或收藏库全部内容。
- **动图**：服务端将评论图片转码为 WebP，网页端资源通常不含动画帧（见 `VALIDATION.md`），本工具如实标注为静态。
- 图片链接带时效；链接过期会显示失败原因，需回到页面重新加载并重新采集。
- 单会话最多 500 个候选；单文件 20 MiB；单次 ZIP 最多 200 张或 100 MiB 原始数据。
- 刷新小红书页面后采集连接会中断，需要重新点击扩展图标。

## 隐私

- 不读取 Cookie、不导出账号信息、不发送任何数据到第三方服务。
- 仅在用户点击后注入脚本，仅读取当前页面的评论图片并保存到本机。
- ZIP 的 `manifest.json` 不包含带签名的图片地址或完整评论文本。
